## Структура CAllocator'а
```c
typedef struct CBlock {
    size_t size;
    struct CBlock *next;
    struct CBlock *previous;
    bool free;
} CBlock;

typedef struct CAllocator {
    void *memory;
    size_t capacity;
    size_t used;
    CBlock *blocks;
    CBlock *hint;
    bool own_memory;
    bool initialized;
} CAllocator;
```

`CAllocator` состоит из:
- `*memory` — указатель на начало управляемой области памяти;
- `capacity` — размер области управляемой памяти в байтах. `capacity` включает как пользовательские области блоков, так и
    занимаемые ими заголовки `CBlock`;
- `used` — количество памяти, выделенной пользователю в данный момент;
- `*blocks` — указатель на первый [`CBlock`](#cblock) (далее просто «блок») двусвязного списка блоков;
- `*hint` — указатель на блок, с которого начинается следующий поиск свободного блока;
- `own_memory` — определяет, принадлежит ли allocator'у управляемая область памяти;
- `initialized` — определяет, прошёл ли allocator инициализацию; пока флаг не установлен, все операции с allocator'ом
    игнорируются.

### `CBlock`
`CBlock` — метаданные блока управляемой памяти. Метаданные лежат непосредственно перед пользовательскими данными. Поля:
- `size` — размер доступной пользователю памяти в байтах;
- `*next` — указатель на следующий блок;
- `*previous` — указатель на прошлый блок;
- `free` — свободен ли блок.

Блоки лежат подряд и покрывают всю область без пропусков; все указатели, возвращаемые `c_alloc`, выровнены под `_Alignof(long
double)`. Сумма `sizeof(CBlock) + size` по всем блокам всегда равна `capacity` — этот инвариант проверяется валидатором после
каждой операции в стресс-тестах.

## Структура памяти
```c
static const size_t CA_ALIGNMENT = _Alignof(long double);
```
Allocator управляет непрерывной областью `memory` размером `capacity` байт. Блоки в памяти лежат следующим образом (ASCII-схема
снизу):
```text
┌──────────────┬────────────────┐
│   CBlock     │  user data     │
└──────────────┴────────────────┘
```
Данные пользователя начинаются сразу после заголовка; для внешней арены `cinit` требует, чтобы `memory + sizeof(CBlock)` был
выровнен, иначе инициализация отклоняется (для самовладеющей арены `malloc` гарантирует выравнивание).

Из раскладки следуют инварианты: сумма `sizeof(CBlock) + size` по всем блокам равна `capacity`, а `used` равен сумме `size`
всех занятых блоков.

При освобождении блок объединяется со свободными соседями. При объединении заголовок поглощённого блока перестаёт существовать
как отдельный элемент списка.

Самовладеющая арена может расширять управляемую область памяти.
При расширении адрес `memory` может измениться, поэтому внутренние указатели на блоки должны быть скорректированы.

## Список блоков
Каждый блок входит в единый двусвязный список, начинающийся с `CAllocator::blocks`. Порядок блоков в списке соответствует их
физическому порядку в управляемой области памяти: `next` указывает на следующий блок, а `previous` — на предыдущий.

Первый блок имеет `previous == NULL`, последний — `next == NULL`.

Указатели `next` и `previous` не используются для определения физического расположения блока, а поддерживают двусвязный список
и позволяют за O(1) переходить к соседним блокам.

## Выделение памяти
Запрос округляется вверх до `CA_ALIGNMENT` (переполнение — `NULL`). Поиск свободного блока начинается с `*hint`: он проверяется
за O(1) по связям соседей, при неудаче поиск начинается с головы списка. Сканирование ограничено бюджетом `capacity / (sizeof(CBlock) + CA_ALIGNMENT) + 2` —
реальный список не может быть длиннее, поэтому полный обход всегда выполняется.

Если подходящий блок не найден до конца списка, поиск оборачивается: продолжается от головы до стартового блока. Если блок так и
не найден:
- внешняя арена — возвращается `NULL`;
- самовладеющая арена — выполняется рост (см. «Рост самовладеющей арены»).

Найденный блок помечается занятым, `used` увеличивается на его `size`. Если остаток
`block->size - size >= sizeof(CBlock) + CA_ALIGNMENT`, остаток оформляется отдельным
свободным блоком; иначе блок отдаётся целиком. `*hint` указывает на новый свободный
блок либо на следующий за выданным.

Худший случай — полный обход списка, O(n); при последовательных аллокациях поиск стартует с места
последней операции и находит блок за O(1).

## Освобождение
Данные лежат сразу после заголовка, поэтому заголовок ищется как `ptr - sizeof(CBlock)` и
проверяется за O(1) по границам области и связям `*next` или `*previous`; если проверка неоднозначна
(блок без соседей), выполняется полный обход. `NULL`, чужой указатель и повторное освобождение
игнорируются.

Блок помечается свободным, `used` уменьшается на его `size`, после чего он сливается (merge) со
свободными соседями: сначала с правым, затем с левым. Соседний свободный блок поглощается вместе
со своим заголовком. `*hint` указывает на выживший после слияния блок.

Следствие: свободные блоки никогда не граничат друг с другом.

## Изменение размера
`ptr == NULL` — как `c_alloc`; `size == 0` — как `cfree`.

Уменьшение: если остаток `block->size - aligned >= sizeof(CBlock) + CA_ALIGNMENT`, хвост отрезается
как свободный блок и сливается с правым соседом; `*hint` указывает на этот хвост. Иначе блок не
меняется.

Увеличение:
- на месте — если правый сосед свободен и `combined = block->size + sizeof(CBlock) + next->size`
  достаточен, блок поглощает соседа; остаток оформляется свободным блоком (и сливается с правым
  соседом) либо, если он меньше порога, поглощается целиком;
- переезд — новый `c_alloc` + копирование данных + освобождение старого блока. Для самовладеющей
  арены `c_alloc` может вызвать рост, а рост — перенос области: старый `ptr` становится
  недействительным. Поэтому данные сначала копируются во временный буфер, затем выполняется
  `c_alloc`, копирование обратно, и старый блок освобождается по сохранённому смещению заголовка в
  новой базе. Неудача `c_alloc` оставляет исходный блок нетронутым.

## Рост самовладеющей арены
Вызывается, когда поиск в `c_alloc` не нашёл подходящий блок. Новая ёмкость —
`max(old * 2, old + needed + sizeof(CBlock) + CA_ALIGNMENT)` с проверками переполнения. Область
перевыделяется через `realloc`:

- если область переехала, все внутренние ссылки (`*blocks`, `*hint`, `*next`, `*previous`)
  пересчитываются на величину сдвига — заголовки остаются на прежних смещениях;
- добавленные байты: свободный хвостовой блок увеличивается, либо в конце создаётся новый
  свободный блок;
- `*hint` указывает на хвост.

Указатели, полученные пользователем до роста, могут стать недействительными (область переехала);
занятые блоки при этом не теряются и освобождаются при `creset` или `cdestroy`.
